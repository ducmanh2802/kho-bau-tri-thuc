1) LỖI GÌ

2) LỆNH TÁI LẬP (không cần máy chủ)
   Sao đúng tree của commit được tag rồi chạy npm cùng phiên bản như CI:
     mkdir -p /tmp/ci2 && git archive 7d92246 | tar -x -C /tmp/ci2 && cd /tmp/ci2
     npx --yes npm@10 ci --no-audit --no-fund        =>   EXIT=1

3) ĐỐI CHỨNG TRÊN CÙNG TREE (nên lỗi không tái hiện trên máy phát triển)
     npm ci --no-audit --no-fund   (npm 11.6.2 + Node v24.12.0, Windows)  =>  EXIT=0
     "added 158 packages in 24s"
   npm 11 tự suy ra hai gói `@emnapi/*` còn thiếu trong lock nên vẫn cài được; npm 10 — bản mà
   `actions/setup-node@v4` với `node-version: "22"` mang theo — từ chối và báo EUSAGE.
   Vì vậy `npm run verify` trên máy Windows **xong vẫn không chứng nhận CI**; đây là cổng máy chủ,
   không phải cổng máy lokal.

4) VÌ SAO "3. Browser QA" BÁO success DÙ JOB THẤT BẠI
   `03-qa-browser.yml:30` đặt `continue-on-error: true` cho job (comment ngay trên nó: "chặn merge…
   Xoá dòng continue-on-error khi nó xanh liên tiếp vài lần trên main"). Run kết luận `success` trong
   khi job `golden path trên Chromium` kết luận `failure`, bước Install `failure` và hai bước sau
   `skipped`. Lech "run success / job failure" là do chính lá chắn đó, không phải probe xanh.

5) HỆ QUẢ CHO RELEASE
   Điều kiện người dùng chốt là "tag v1.1.0 **sau khi luồng nghiệm thu xanh**". Tag đầu tiên đóng
   trên `7d92246` thoả cổng máy (`npm run verify` EXIT=0) nhưng KHÔNG thoả cổng máy chủ (CI đỏ ở
   Install) ⇒ hoặc sửa lockfile rồi đóng tag lại trên HEAD có CI xanh, hoặc để release dừng ở
   trạng thái "đã tag, CI đỏ". Chọn vế đầu: lockfile là nguồn thật (`AGENTS.md` §1.6) và lỗi nằm ở
   lock, không ở code.
